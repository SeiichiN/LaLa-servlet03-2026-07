はい、一般的には**パスワードだけは再表示しないほうがよい**です。

理由は、パスワード欄に

```jsp
<input type="password" name="pass"
    value="<c:out value="${account.pass}" />">
```

と書くと、画面上では「●●●●」のように隠れて見えますが、実際には HTML の `value` 属性に平文のパスワードが埋め込まれます。

ブラウザの「ページのソースを表示」や開発者ツールを使えば、

```html
<input type="password" name="pass" value="1234">
```

のように見えてしまいます。

また、

* ブラウザのキャッシュ
* メモリ上のデータ
* ログ出力のミス
* XSS（クロスサイトスクリプティング）の脆弱性

などによって、意図せず漏れる可能性もあります。

そのため、パスワード確認画面から入力画面へ戻る場合でも、

```jsp
<input type="password" name="pass">
```

として、もう一度入力してもらう設計がよく採用されます。

他の項目については、

* ユーザー ID
* メールアドレス
* 名前
* 年齢

を `value` に入れて再表示すること自体は、ユーザビリティの面から普通に行われます。入力ミスがあったときに、すべてを最初から入力し直す必要がなくなるからです。

ただし、実際のサービスでは、これらについてもサーバ側で必ず検証します。`value` に表示されている値は、利用者が開発者ツールで自由に書き換えられるため、

```java
String age = request.getParameter("age");
```

で受け取った値を、そのまま信用してはいけません。

ちなみに、最近の Web サービスでは、パスワード確認画面自体を作らず、

1. 入力画面でパスワードを入力する。
2. 「パスワード確認用」の入力欄でもう一度入力する。
3. サーバ側で一致を確認する。
4. そのまま登録する。

という流れにすることも多いです。

なお、細かい点ですが、

```html
<a href="ReturnTopServlet">
    <button type="button">トップへ</button>
</a>
```

という書き方は HTML としてあまり推奨されません。次のように、どちらか一方にするのがよいでしょう。

```html
<a href="ReturnTopServlet">トップへ</a>
```

または

```html
<button type="button"
        onclick="location.href='ReturnTopServlet'">
    トップへ
</button>
```

です。
